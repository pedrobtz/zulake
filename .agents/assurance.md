# Assurance

How this package meets the shared `assurance.md` rules. CI checks this
file (r-actions `assurance.yml`), so keep the headings and table
columns as they are.

- **Statuses:** a cell is a fact, `gap #<issue>` or `n/a: <reason>`.
- **Started:** 2026-11-26, Stage 0, before any code; each stage filled
  its rows.
- **Checked:** 2026-11-26, [Stage 8](roadmap.md#stage-8--assurance): each
  row names its tests, and each was opened and seen to compare against
  the oracle the row names; the kinds lifecycle and emits, the Objects
  table and seven Limits rows were added.

## Kinds

`untrusted-input` `spec` `lifecycle` `emits`

Evidence (Stage 8): untrusted-input, the log's JSON and Parquet, the
deletion-vector files and Azure's answers, written by other programs;
spec, the Delta protocol, Z85 (RFC 32) and CRC-32; lifecycle, the
credential handle every Azure snapshot holds, an environment with a
finalizer that keeps the token in a registry beyond the call; emits, the
Blob REST requests zulake writes for Azure to read. zulake writes no
file.

## Boundaries

One row per boundary the package crosses. An oracle knows the answer:

- a conformance suite or test vectors;
- a reference implementation;
- a round trip;
- equivalent inputs compared;
- the bytes the other side received.

"No crash" is not an oracle. The reference implementation is `deltalake`
1.7.0, whose answers Stage 1 commits under
`tests/testthat/fixtures/answers/` and `oracle.yaml` (own) regenerates and
diffs; `expect_oracle()` in `tests/testthat/helper-oracle.R` compares
against them (its own tests: `tests/testthat/test-fixtures.R`).
