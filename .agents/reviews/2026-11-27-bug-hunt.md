# zulake bug hunt, 2026-11-27

Commit `7116140`. Hunters: 3 on Fable, one at a time, each blind to the
others' reports:

1. the R layer: exported arguments, the filter language, typed values,
   time travel, hostile sessions;
2. decoding: log listing, replay, checkpoints, column mapping, deletion
   vectors, the read pipeline;
3. the Azure backend and long-lived objects: URI parsing, requests,
   listings, errors, the credentials registry, the per-open cache, fork
   and serialization.

Coordinator on Opus 5.5. Built here: everything. zulake has no `src/`, and
the Azure layer ran against `azure_fake()`, a scripted loopback HTTP server
and Azurite 3.35.0. The oracle was `deltalake` 1.7.0, or PROTOCOL.md where
`deltalake` is lenient. Unverified: Windows paths in the cache, R before
4.3.0, and a real ADLS Gen2 account (#24).

Every reproduced trigger below was re-run by the coordinator against a
fresh install of `7116140`. The probes that reproduced are in
[`2026-11-27-bug-hunt-probes/`](2026-11-27-bug-hunt-probes/), one folder
per hunter; their tables are rebuilt by the `mk*.py` and `p*.py` scripts
there.

Links point at the pinned commit:
`https://github.com/pedrobtz/zulake/blob/7116140/<file>#L<n>`.

Severity: no finding is *high* (memory safety, wrong bytes on the wire or
on disk). *medium* is a wrong result or a broken documented contract, and
is filed `required`; *low* is filed `suggestion`.

## 1. `is.na()` on a `long` column drops rows the read returns as NA — #111, medium, reproduced

- Where: `R/filter.R:769`, `R/filter.R:821-823`.
- Trigger: a `long` column with values past 2^53 - 1. `lake_read(tbl,
  filter = is.na(i64))` returns 3 rows, while `subset()` of the
  unfiltered read returns 7. Four of those rows are values past 2^53 that
  qio returns as `NA` with a warning. `lake_files(filter = is.na(i64))`
  keeps 1 of 4 files. With `int64 = "integer64"`, the value -2^63 reads
  as bit64's NA and is lost the same way.
- Cause: a `nullCount` of 0 is taken to mean that no row reads as NA. #79
  made an exception for `integer` at -2^31; `long` has the same problem.
- Fix: on `long`, prune `is.na()` on the null count only when the file's
  bounds are known and inside ±(2^53 - 1) for `double`, or above -2^63 for
  `integer64`.
- Family: 3 (class fixed as instance). Siblings checked: `integer` (fixed
  in #79); `%in% NA` and `| is.na()` fail with `long` as well.
- Test the suite lacked: a `long` column with values at ±(2^53 - 1),
  ±2^53 and -2^63 and a null count of 0, where `is.na()` read with
  pruning must equal `subset()` in both `int64` modes.

## 2. Decimal partition values the comparator cannot read are accepted — #112, medium, reproduced

- Where: `R/protocol.R:263-281` accepts the value; `R/compare.R:58`
  (`exact_pattern`) and `R/compare.R:326` compare it.
- Trigger (hunters 1 and 2, independently): a `decimal(10,2)` partition
  value spelled `.5`, `5.` or `-.5`. It opens and reads as 0.5, but no
  comparison matches it: `pdec == 0.5` finds nothing, and `pdec > -1000`
  drops the file. A value with more digits than the type allows (`12.345`
  in `decimal(10,2)`, `123.456` in `decimal(4,2)`, `123456789.00` past the
  precision) also reads. `lake_files(filter = pdec == 12.345)` keeps its
  file, and the row filter then drops the row. `deltalake` refuses every
  one of these tables.
- Cause: the validator's number pattern is wider than the comparator's,
  and nothing checks the scale or the precision.
- Fix: in `check_partition_values()`, accept only what `exact_parse()`
  parses, and refuse a value with more fraction digits than the scale or
  more integer digits than precision minus scale, as a corrupt log.
- Family: 1 (one value, two meanings: the validator's pattern and the
  comparator's).
- Test the suite lacked: decimal partition spellings `.5`, `5.`, `-.5`,
  `1e2` and `12.345`, and a value past the precision, each refused as
  `deltalake` refuses it.

## 3. `is.na()` of a binary column means two things — #113, medium, reproduced

- Where: `R/filter.R:539` (the pruning atom counts `NULL` as NA) and
  `R/filter.R:456` (a row-evaluated node calls base `is.na()`, which is
  FALSE for `NULL`).
- Trigger: fixture `zl-types`, column `b`.
  - `is.na(b)` returns the null row.
  - `is.na(b) == TRUE` and `xor(is.na(b), FALSE)` return nothing.
  - `is.na(b) == FALSE` returns all 6 rows.
  - `b %in% NA` returns nothing, though `s %in% NA` does return the null
    row of a string column.
- Expected: `?lake_read` says that `is.na()` is TRUE for a null value of
  a list column, with no exception.
- Fix: give the row evaluator an `is.na()` that is TRUE for `NULL`
  elements of a list column, and make `%in% NA` the same.
- Family: 1.
- Test the suite lacked: equivalent forms of `is.na()` on every list
  column (`== TRUE`, `xor`, `!`, `%in% NA`) give the same rows.

## 4. A comma decimal separator in `LC_NUMERIC` breaks exact filters — #114, medium, reproduced

- Where: `R/compare.R:204` (`sprintf("%.15g")` on literals) and
  `R/compare.R:326,328` (`sprintf("%.*f")` on rows), read back by
  `exact_parse()`, which expects `.`.
- Trigger: `Sys.setlocale("LC_NUMERIC", "de_DE.UTF-8")`.
  - `dec > 0` returns 0 rows instead of 5.
  - `dec15 == 1e-05` returns 0 rows instead of 1.
  - `dec == 12.3`, `a > 50.5` and `pdec == 12.3` fail with the base error
    "missing value where TRUE/FALSE needed".
- Cause: `sprintf()` uses the C library's locale for the decimal point.
- Fix: replace `,` by `.` in the output of those `sprintf()` calls, or set
  `LC_NUMERIC` to C around them.
- Family: none. This is the R-layer "hostile session" case of
  `correctness.md`.
- Test the suite lacked: the hostile-locale helper (#81) also sets
  `LC_NUMERIC` to a comma locale, and checks exact-kind filters against
  `subset()`.

## 5. A statistic of the wrong JSON type is used as a bound — #115, medium, reproduced

- Where: `R/filter.R:717` (`leaf_text()` maps any logical to "1" or "0").
- Trigger: `zl-basic` version 0 with `maxValues.id` set to `true` (`id`
  is `long`, with values 1 to 3). `id > 2` returns 0 rows, because the
  file is pruned as if its maximum were 1.
- Expected: a statistic that is not of the column's type is unknown, as a
  string or `null` already is, and the file is kept.
- Fix: in `leaf_text()`, use a logical only for `boolean` columns, and
  treat it as unknown otherwise.
- Family: 1.
- Test the suite lacked: for each Delta type, statistics of every other
  JSON type keep the file.

## 6. A column `a.b` beside a struct `a` makes the table unreadable — #116, medium, reproduced

- Where: `R/read.R:238-246`, and `qio::read_parquet(columns =)` in
  `read_piece()`.
- Trigger: the schema `[id long, a struct<b long>, "a.b" long]`.
  `lake_read()` fails with qio's unclassed "Ambiguous Parquet column:
  `a.b`". `deltalake` reads `1|{'b': 7}|42`. Dotted column names are
  legal in Delta.
- Cause: the flat column is passed to qio as a dotted path, which also
  matches the nested leaf.
- Fix: select top-level columns in a way qio cannot read as a path (by
  index, or by a path vector if qio has one). If it can't, refuse the
  read with `zulake_error_column_unreadable` naming the column.
- Family: 1.
- Test the suite lacked: a fixture with a dotted top-level column next to
  a struct of the same prefix, compared with `deltalake`.

## 7. A valid compaction file with two tombstones of one path is refused — #117, medium, reproduced

- Where: `R/replay.R:256` (`check_one_per_path()` also applies to
  compaction files).
- Trigger: commit 1 removes `(f0, none)` and adds `(f0, dvA)`; commit 2
  removes `(f0, dvA)` and adds `f1`. The compaction file `1.2` holds both
  tombstones, as action reconciliation keyed by `(path, dvId)` requires.
  zulake refuses it as a corrupt log and doesn't fall back to the
  commits; `deltalake` reads the commits.
- Cause: the rule for one version (#106) is applied to a reconciled range.
- Fix: in a compaction file, check tombstones and adds by `(path, dvId)`
  only. Also, a compaction file the checks refuse should be passed over
  for its commits, as an unreadable one is (#69).
- Family: 3.
- Test the suite lacked: a compaction file over a range in which one path
  changes its deletion vector twice.

## 8. A partition column's values differ from a data column's of the same type — #118, medium, reproduced

- Where: `R/values.R:179-180` (`float` uses `partition_double()`), and the
  conversions of binary and timestamp partition values.
- Trigger:
  - `float` partition values `1.1`, `16777217` and `1e39` read as
    1.1000000000000001, 16777217 and 1e39. `deltalake`, and zulake for a
    `float` data column (design §8), give 1.100000023841858, 16777216 and
    Inf.
  - A `binary` partition column is a character vector; a `binary` data
    column is a list of raw vectors.
  - A partition timestamp with 9 fractional digits is rounded to the
    microsecond, where `deltalake` truncates it.
- Fix: round `float` partition values through single precision, return
  binary partitions as a list of raw vectors, and truncate partition
  timestamps to the microsecond.
- Family: 3.
- Test the suite lacked: for every type that can be a partition, the
  same value as a partition and as a data column reads `identical()`.

## 9. A data file's column type is not checked against the schema — #119, medium, reproduced

- Where: `R/read.R:218` (only nested and wide-decimal types are vetted),
  and `R/read.R:467` (classes are compared only across pieces).
- Trigger:
  - A schema `long` over a file of strings returns a character column.
  - A schema `integer` over an INT64 file holding 2^40 returns
    1099511627776.
  - A `long` column read from INT32 and INT64 files is refused as corrupt.
    `deltalake` refuses the first two and upcasts the third.
- Expected: a column's R type follows `lake_schema()`, from one file and
  one snapshot to the next.
- Fix: compare each file's physical type with the Delta type. Refuse a
  mismatch with `zulake_error_corrupt_log` naming the file, and widen
  INT32 to the `long` mapping.
- Family: 4 (the specification's second case: a file that disagrees with
  the schema).
- Test the suite lacked: a hostile file per Delta type, with another
  physical type in it.

## 10. The schema is not validated at open — #120, medium, reproduced

- Where: `snapshot_build()` and `check_metadata()` (`R/replay.R`).
- Trigger: each of these opens, and some then misbehave on read.
  - Types zulake doesn't know (`varchar(10)`, `STRING`, `variant` without
    its feature) and a field with no `type` are read as whatever the file
    holds.
  - Two fields with one name open and read as one column.
  - A field with no `name` or with `""` opens, then `lake_read()` fails
    with `subscriptOutOfBoundsError`.
  - Two fields with one physical name in name mode fail with "`columns`
    must not contain duplicates".

  `deltalake` refuses each of these at open.
- Fix: validate the schema once in `snapshot_build()`. Refuse an unknown
  type, duplicate names, a missing name and duplicate physical names, as
  `zulake_error_corrupt_log`, or `zulake_error_unsupported_feature` for a
  type that needs a feature.
- Family: 4.
- Test the suite lacked: hostile schemas for each case, refused at open
  by name.

## 11. A JSON line holding two actions applies both — #121, medium, reproduced

- Where: `R/replay.R:208-214`.
- Trigger: the single line `{"add":{...c...},"remove":{"path":"a",...}}`.
  zulake applies both, so files `b` and `c` remain. `deltalake` applies
  only the add, so `a`, `b` and `c` remain.
- Expected: PROTOCOL.md: "every action is stored as a single-line JSON
  document". A line with two actions is malformed, and the readers
  disagree in silence, the #102 case.
- Fix: refuse a line with more than one action key as
  `zulake_error_corrupt_log`, naming the file and line.
- Family: 4.
- Test the suite lacked: a hostile log with two actions on one line.

## 12. A log file cut short is replayed as if whole — #122, medium, reproduced

- Where: `R/azure.R:576` (`get()` returns the body unchecked), with the
  size from `list_files()` (`R/azure.R:490`) never compared.
- Trigger: a commit body that ends early at a line boundary, served with
  no `Content-Length` and closed. zuhttp accepts that. On `zl-basic`,
  cutting commit 2 gives 6 rows instead of 3, and cutting commit 3 gives
  1 row, with no error.
- Expected: data files are checked against the log's size (§4.1), and log
  files have their listed size, which nothing uses.
- Fix: compare each log file's length with its listed size (commits,
  checkpoints, sidecars, compaction files, `_last_checkpoint`). On local
  disk, compare with `file.size()`. Refuse a difference as
  `zulake_error_storage`.
- Family: 1 (received bytes against listed bytes).
- Test the suite lacked: a mock answer one line short for each kind of
  log file, refused before replay.

## 13. Some errors are unclassed or misclassed — #123, medium, reproduced

- Where: `R/read.R:238` (`qio::read_plan` and `read_piece()` are not
  wrapped), `R/read.R:624-629`, `R/dv.R:231-238` and `R/open.R`.
- Trigger:
  - A data file that is truncated, empty or not Parquet gives qio's
    `simpleError`. A corrupt page gives one that doesn't name the file.
  - A cache directory that is a file or read-only gives `simpleError`
    "cannot open the connection" and a base warning.
  - The latest commit listed twice gives `simpleError` "wrong arguments
    for subsetting an environment".
  - A missing deletion-vector file is called a corrupt log ("in a file of
    NA bytes").
- Expected: every error is a `zulake_error_*`, and a read error names the
  file (CLAUDE.md, `R/conditions.R`).
- Fix: wrap the qio calls in `read_piece()` into
  `zulake_error_storage(path =)`; check the result of `dir.create()`; give
  a HEAD 404 on a vector "no such file"; see #124 for the listing.
- Family: none.
- Test the suite lacked: for each read stage, a broken input that must
  give a classed error naming the file.

## 14. A blob listed twice is kept twice — #124, low, reproduced

- Where: `R/azure.R:545-566` (pages are bound without removing
  duplicates).
- Trigger: a listing that names one commit twice. `lake_log()`,
  `lake_versions()` and `lake_history()` then list that version twice.
  For the latest commit, `lake_open()` fails (#123).
- Fix: refuse a name that appears twice in a listing, as
  `zulake_error_storage`.
- Family: 4.
- Test the suite lacked: a paged fake that repeats one name.

## 15. A listing whose markers never repeat is followed without bound — #125, low, reproduced

- Where: `R/azure.R:498-543`.
- Trigger: a server that returns an empty page with a new marker every
  time. 3000 requests went out before the fake stopped them.
- Fix: stop after a bounded number of empty pages in a row, or after a
  page cap, with `zulake_error_storage`.
- Family: none.
- Test the suite lacked: a limit row for listing pages, straddled.

## 16. URI and token checks have gaps — #126, low, reproduced

- Where: `R/azure.R:131-136`, `R/azure.R:333`, `R/storage.R:34`,
  `R/read.R:605`.
- Trigger:
  - A container name ending in a newline is accepted, because `$` in a
    PCRE pattern matches before a final `\n`, and a request goes to
    `lake%0A`.
  - A leading space turns an Azure URI into a local path.
  - `a%zzb` and `a%` pass as literal text.
  - A token with a no-break space or `café` is sent, and `"Bearer"` alone
    is sent as `Bearer Bearer`.
  - The cache directory check is a prefix test, which accepts
    `zulake-cache-evil/`.
- Fix: anchor with `\\z` (or use TRE). Trim nothing and refuse
  surrounding white space. Refuse an invalid percent escape. Allow only
  visible ASCII in a token. Compare the cache directory with
  `dirname(hit)`.
- Family: 3.
- Test the suite lacked: a URI and token matrix that includes a final
  newline, surrounding space, bad escapes and non-ASCII.

## 17. Redirects are followed — #127, low, reproduced

- Where: zuhttp's default redirect handling, through `azure_request()`.
- Trigger: a 302 or 307 to another origin is followed. zuhttp drops
  `Authorization` there, so the token doesn't leak, but the target then
  supplies the log or data, unauthenticated.
- Expected: §4.1 says every request goes to the account's Blob endpoint.
- Fix: turn redirects off in the client zulake builds, so that a 3xx is a
  `zulake_error_storage`.
- Family: 4.
- Test the suite lacked: a 307 to another port, asserting no request
  reaches it.

## 18. Numbers in the log spelled with a fraction or an exponent — #128, low, reproduced

- Where: `R/int64.R:240`; `mark_numbers()` protects only `^-?[0-9]+$`.
- Trigger:
  - `"size":9007199254740993.0` or `9.007199254740993e15` reads as
    9007199254740992 under `int64 = "integer64"`. Under `"double"`, the
    error quotes the rounded value.
  - `numRecords` written as `3e0` is refused as "not a whole number",
    while a `size` of `4.86e2` is accepted.
- Fix: refuse a 64-bit field past 2^53 that is not an integer token. Read
  integral exponent forms the same way in every field.
- Family: 1.
- Test the suite lacked: each 64-bit field in `1.0`, `1e0`, `x.0` past
  2^53 and `xe15` forms, read the same in both `int64` modes.

## 19. Smaller items — #129, low, reproduced

- **Checkpoint content.** A checkpoint with invalid content (a null
  `add.path`, two `protocol` rows, zero rows) refuses the table even
  when every commit is present. A truncated checkpoint is passed over.
  Design §4.2 doesn't list these cases.
- **Protocol shapes.** `readerFeatures` with reader version 1 or 2, and
  version 3 with no `readerFeatures`, are accepted. `deltalake` refuses
  them as invalid.
- **Design text.** Design §4.2 (#52) says `deltalake` 1.7.0 makes file
  times increasing as zulake does. On tables whose file times are equal
  or go backwards, it opens other versions: for example, 5000 ms on four
  equal times opens version 0 in zulake and 3 in `deltalake`. zulake's
  rule is the history manager's, so the sentence about `deltalake` needs
  correcting, and a fixture point between such commits needs adding.
- **Error wording.**
  - `lake_changes(from = 1.5)` names `version` in its error.
  - Literal errors from `lake_read()` carry the hint meant for
    `lake_files()`.
- **Speed.** `%in%` costs about 0.19 ms per value: 3.8 s for 20,000
  values on 12 rows.

## Cross-cutting

- **Two parsers of one value.** Findings 2, 3, 5 and 11 are one value
  read two ways: a validator and a comparator, the pruning atom and the
  row evaluator, a statistic and its column type, a line and its
  actions. That is family 1, and #102 and #107 fixed the same shape. A
  candidate rule for `correctness.md`: *where one value is read by two
  code paths (validation and use, pruning and filtering), one function
  reads it for both, or a test feeds the same inputs to both and
  compares.*
- **Fixes applied to one type.** #79 fixed `integer`, and `long` was left
  (finding 1). #106 wrote a rule for commits, and compaction files took
  it on wrongly (7). `float` shares the `double` path (8). That is family
  3 again.
- **Bytes not checked against their stated length.** Data files and
  deletion vectors are checked against the length the log gives them.
  Log files are not, though the listing gives their size (12).
- **What the oracle cannot see.** `deltalake` is lenient in places
  (two actions on a line, an absent deletion-vector offset, a log that
  starts at commit 1). There the protocol text was the oracle. On the
  offset, the protocol sides with zulake.

## Held: what was probed and stood

- **Filters.** 17,629 filters (17 columns of every primitive type × 60
  literals × 17 shapes), pruned against stats-stripped against
  `subset()`. The only difference was finding 1. The partition-column
  matrix and about 2,900 filters over 18 fixtures, in both `int64` modes,
  held too.
- **Hostile session.** `LC_ALL=C`, `tr_TR`, `OutDec=","`,
  `scipen=-5`, `digits=3`, `warn=2`, `TZ` Pacific/Chatham and
  America/Sao_Paulo: 1,029 accessor results over 31 fixtures were
  `identical()` to the base session.
- **Time travel.** 293 timestamps from year 0001 to 9999. Every version
  of every fixture opens at its own time. Each commit was probed at
  ±1 µs and ±1 ms in three time zones. Bad timestamp arguments are
  refused.
- **Arguments and routes.** Numeric arguments with 26 hostile values.
  `lake_open(version =)` equals `lake_load()`. `lake_count()` equals the
  read and `lake_walk()`. `lake_changes()` equals the set difference
  for 428 version pairs.
- **Replay against `deltalake`.** About 300 tables compared whole:
  - remove and re-add, metaData and protocol changing mid-log, unknown
    actions and fields;
  - path encodings, version gaps, corrupt commits;
  - compaction selection;
  - checkpoints (classic, multi-part, V2 Parquet and JSON with sidecars)
    equal to their commits at 6,000 adds;
  - `_last_checkpoint` forms, log file names, column mapping in name
    mode, and partition values at every type limit.
- **Deletion vectors.** Containers at 2^16 boundaries, 1 to 6
  containers, rows n-1, n and 2^32, cardinalities up to 123,457. Wrong
  sizes, offsets, CRC and version are each refused by name. Inline,
  `p` and prefixed vectors all read.
- **Azure.**
  - The three URI forms give identical requests, and every refusal
    leaks no query or userinfo.
  - The 401 refresh and `credentials()` failure sequences work.
  - Error mapping covers every status and code, paging with
    awkward markers works, and every Range and HEAD straddle holds.
  - The absolute-path rule (#76) holds in every form.
- **The token.** No 8-character piece of it was found in any
  serialization, print, condition, warning, option, client or cassette,
  across readRDS in a new process, garbage collection, fork (90 of 90
  correct), interrupts and half-failed downloads.
- **Cache.** Sizes one byte off are refused with nothing cached. After a
  failure on file 2, a retry fetches only that file. Copies that were
  grown, shrunk or deleted are fetched again.

## Not reached

- **Too large or too slow to run:** listings of more than 5,000 blobs on
  Azurite, bodies above 2 GB, the 600-second timeout, and
  deletion-vector rows at or past 2^53.
- **Platforms and environments:** Windows cache paths, R before 4.3.0,
  and the `random_hex()` fallback.
- **Inspection functions:** a field-by-field comparison of
  `lake_schema()`, `lake_protocol()`, `lake_properties()` and the others
  with the answers (only session independence was checked), and
  `lake_changes()` across a checkpoint or a compaction file.
- **Writers not tried:** checkpoints written by Spark with
  `stats_parsed`, and Spark-written timestamp partitions before 1970.

## Not reproduced, and by design

- **A deletion vector with no `offset`.** PROTOCOL.md says "Interpret as
  `0` if absent", so zulake is right and `deltalake` 1.7.0, which reads
  from byte 1, is wrong. Not filed.
- **By design, not filed:**
  - a stale `_last_checkpoint` refuses the table (§4.2);
  - a log that starts at commit 1 with no checkpoint is refused (a table
    starts at commit 0 or at a checkpoint);
  - a misspelt column that matches a variable is a constant (D8, §6);
  - text against number and timestamp columns (§6);
  - cache files kept until the session ends (§4.3);
  - `lake_history()` re-reading commits, which is under After 0.1.0;
  - stale `lake_actions()` against `lake_changes()` (#104);
  - no retry on 503 or 429, which the design doesn't promise.
- **Not reproduced:** none. Every reproduced trigger reproduced again.

## Yield

- **Hunters:** 3, one at a time, on Fable. Hunter 1 ran about 21,000
  probes, hunter 2 about 300 tables against `deltalake`, and hunter 3
  about 20 scripts against a mock, a loopback server and Azurite.
- **Findings:** 19 filed. 13 are medium (`required`): findings 1 to 13.
  6 are low (`suggestion`): findings 14 to 19. None are high.
- **Wrong rows in silence:** findings 1, 2, 3, 4, 5, 11 and 12.
- **Found by more than one hunter:** 1 (finding 2, by hunters 1 and 2).
- **Unverified:** Windows, R before 4.3.0, and live ADLS Gen2.
